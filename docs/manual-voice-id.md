# GUI 手動設定 Voice ID

在「單人配音」頁面的角色聲線卡片右側，使用 **手動設定 Voice ID**。不需要手動修改 JSON，也不需要先執行一次語音生成才能儲存。

## 操作

1. 從有權使用的 Fish Audio 聲音取得 Voice ID，直接輸入或以 Ctrl+V 貼上。請貼上識別碼本身，不是聲音頁面網址或 OpenRouter API Key。
2. 檢查欄位下方的「下一次生成」來源與實際 ID。
3. 按「儲存 Voice ID」。看到成功提示後，重新啟動會載入此設定。前後空白會去除，ID 大小寫保留。
4. 輸入台詞，再按原有「產生語音」。修改中的有效 ID 也會套用到下一次生成；明確按儲存可以在不生成的情況下保留設定。
5. 不再使用自訂聲音時，按「清除並儲存」，移除全域覆寫。這不會刪除已生成的音檔。

儲存或清除只寫入本機原有的 `fish_tts_config.json`（`custom_voice_id` 欄位），不會呼叫 TTS API、不會進行付費試聽。寫入失敗會顯示錯誤，不會宣稱儲存成功。既有設定檔格式不變；模型、金鑰記憶選項、語速等偏好保留。

## 生效順序與範圍

沿用既有單人配音順序：**有效的手動 Voice ID > 所選角色預設 Voice ID > 不傳 voice 欄位**。留白不是硬編碼到某個固定聲音；省略 voice 時是否有預設聲音，取決於供應商。錯誤的非空 ID 不會偷偷退回其他音色。

手動 Voice ID 是單人配音的全域覆寫，切換角色不會清除。角色的文字聲線標籤與語速邏輯仍保持原樣；需要純粹使用指定音色時，可取消「自動在台詞套用聲線標籤」。已送出的生成請求使用當時的快照，不會因稍後修改 ID 而改變。

多角色劇本與時間軸各自的 Voice ID 設定不受這個欄位影響。本次不增加跨角色批次覆寫，也不改動 MCP/CLI 參數。CLI/MCP 明確使用 `--config` 時仍可讀取同一個 `custom_voice_id` 設定，並依其既有優先順序處理。

## 驗證限制

本機攔截常見網址、疑似 API Key、內部空白／控制字元，以及超過 512 bytes 的識別碼。不強制固定長度或全為十六進位，以免排除合法的供應商 ID。錯誤訊息不回顯可能誤貼的金鑰。

**本機格式驗證與儲存成功不代表 Voice ID 在供應商端存在、可用或已取得授權。** 真正生成仍須有效的 API Key、相容的模型與聲音存取權，並可能計費。

開發驗證：`cargo test --locked`、`cargo test --locked --no-default-features`。新增測試包含輸入正規化、優先顺序、設定序列化／重新讀入、寫入失敗處理，以及無視窗 egui 渲染。這些是離線測試，不代表已完成 Windows 人工點選、付費 TTS 或音質試聽。
