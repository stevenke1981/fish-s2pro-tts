# 以配音工作為中心的介面改善

本次直接修改既有 Rust / egui App。範圍以單人配音工作區與共用音訊完成流程為主，多角色頁面加入工作互斥保護。

## 使用流程

1. 初次啟動：展開連線設定，輸入 OpenRouter API Key；已有設定時預設收合。
2. 寫台詞：主要區域先顯示較大的編輯器，可匯入 UTF-8 TXT / Markdown、儲存文字，或載入範例。
3. 選聲音：左侧選角色、語速與格式；模型及情緒標籤預設收合。
4. 產生：顯示實際模型、格式及語速；缺少金鑰或台詞時停用按鈕並說明原因。
5. 試聽與匯出：完成後即使沒有播放裝置或關閉自動播放，也會載入最新音訊供另存。
6. 找作品：作品庫管理既有音檔；歷史預設收合，避免占用寫作空間。

## 修正與設計理由

- 清空、匯入與套用範例前保留一份台詞，可按「復原替換／清空」取回。這是單次復原，不是自動儲存或完整版本紀錄。
- 工作區可垂直捲動，生成控制列可換行；避免內容超出小視窗而不可操作。
- 背景工作期間定時刷新，無須移動滑鼠才看到結果。
- 單人、整份劇本與單句試聽互斥，避免完成訊息覆蓋其他進行中工作的狀態。
- 共用完成處理會確認音檔寫入結果。失敗時保留記憶體中的音訊、顯示另存指引、不加入不存在的歷史音檔。
- 匯出依目前音訊識別預設副檔名，不受下一次生成格式設定影響；拒絕把 WAV 直接偽裝成 MP3。
- 開啟資料夾支援 Windows、macOS、Linux；失敗時提供錯誤。
- 移除歷史區的一鍵清空，避免誤觸遺失索引。
- 說明金鑰的明文儲存方式，並在金鑰修改後清除舊驗證狀態。

## 驗證狀態與限制

本次環境沒有 cargo / rustc 或桌面顯示服務。尚未完成編譯、原生介面截圖、實際播放及付費 API 測試；此文件是原始碼分析與修改說明，不是已完成的視覺稽核。

加入 Windows / Linux CI，執行 `cargo test --locked` 與 `cargo build --locked`。新增播放器不自動播放仍保留最新音訊、以及 WAV 匯出不得偽裝 MP3 的回歸測試。CI 結果須另行確認。

## 合併前人工驗收

- Windows 在 860×600 與 1120×780、淺色／深色下，檢查文字、捲動與按鈕可達性。
- 空金鑰、空台詞、自訂模型留空時，應有可理解的指引且不送出錯誤請求。
- 匯入含 BOM 的繁體中文 UTF-8 文字、替換範例、清空後復原，確認文字一致。
- 關閉自動播放後生成，可按播放及另存；沒有音訊裝置時仍可另存。
- outputs 設為不可寫入時，結果不得宣稱已儲存，也不得新增虛假歷史項目。
- 單人生成中切到多角色、單句試聽中點整份生成：不可送出重複工作。
- 先生成 WAV 再把下一次格式切成 MP3，另存仍應預設 WAV；手動選 MP3 應明確拒絕。
- 檢查 API 失敗、播放失敗及關閉視窗前台詞另存的流程。
